# Feature inventory (regression checklist)

For coding agents. Read this before rebuilding, redesigning or replacing any existing UI or module.

## Rule

1. Before the change: mark which items below the change touches. Re-read their code; this list can lag.
2. After the change: verify each touched item in a running Obsidian (TAlpha test vault), not only in code. Check stateful controls in every state, in light and dark theme.
3. Fix anything missing before reporting the work as done.
4. If an item cannot or should not be kept, never drop it silently. Report one line each:
   `Dropped/changed: <what> | why: <reason> | impact: <what the user loses>`
   Ask before dropping anything the user interacts with directly.
5. New or changed feature: update this file in the same change.

Source of each section: **[code]** = read from `src/` at 0.30.0; **[readme]** = taken from README.md, covered by `npm run test:*`, not re-read line by line.

## 1. Entry points [code: main.ts]

Command IDs are stable API. Never rename.

- [ ] `sync-all-chats` Sync all chats
- [ ] `sync-claude-chats` "Sync Claude (claude.ai and Claude Code)": every claude.ai account, then Claude Code for every account that has it on; `sync-chatgpt-chats` "Sync ChatGPT (chats and Codex)": every ChatGPT account, then Codex likewise; a part that fails does not stop the next; `sync-lumo-chats`, `sync-gemini-chats` (Gemini, then AI Studio if on)
- [ ] `sync-desktop-app-chats`, `sync-hermes-chats`
- [ ] `sync-ai-memory` Sync AI memory (not part of Sync all)
- [ ] `reconcile-chatgpt-chats` (full check, not only recent changes)
- [ ] `cancel-chatgpt-retry` "Cancel pending chat sync retry": only offered while a retry waits (for any provider) and nothing runs; cancels every waiting retry, the pause itself still applies
- [ ] `stop-sync`: only offered while a sync runs and no stop was asked yet; the only way to stop a running merge (section 6b)
- [ ] `refresh-index`, `move-to-app-layout`, `diagnose-chat-downloads`
- [ ] `merge-chat-copies`: opens the preview; refused with a notice while a sync runs, while a merge waits or while a merge runs
- [ ] `update-active-context` Update Active Context now (section 12); says so when the upkeep is off or the note is missing
- [ ] `hand-over-chat` Hand over a chat to another AI: picker of the 20 newest synced chats, copies the hand-over message (section 12)
- [ ] `test-mobile-connection` Test mobile connection: one GET to `claude.ai/api/organizations` and one to `chatgpt.com/api/auth/session` per account, with the pasted login only (secret storage; never the login window). Report dialog with **Copy**: status, content type, Cloudflare check page yes/no, login accepted/refused; "not tested" when nothing is pasted. Writes nothing to the vault or `data.json`; the report (also sent to the console) holds no secret and no answer text
- [ ] `sync-or-ask` Sync: here, or ask the computer (same as the ribbon icon; see section 10). On mobile `sync-all-chats` does the same
- [ ] Ribbon icon: on a device that asks, "Ask the computer to sync" and a click writes a request (section 10). On a device that syncs: `refresh-cw` "Sync all chats" when idle; `square` "Stop sync" / "Stopping the sync…" plus class `is-syncing` while running; click toggles sync or stop; while a merge runs the label is "Merging chat copies…" and a click only shows how to stop it (section 6b)
- [ ] Status bar item: click stops a running sync (not a merge: it shows how to stop it); `ccs-status-stoppable` (hover style) and aria-label only while stoppable; "merging chat copies, N of M" while a merge runs

## 2. Sync engine, all providers [code: main.ts, sync.ts]

- [ ] One sync at a time; a second manual start shows "A sync is already running." (or the project-list variant)
- [ ] Project-list fetch blocks syncs and cannot be stopped (`exclusive`)
- [ ] Stop ends between two chats; everything saved stays; later accounts in the run are skipped
- [ ] Order of Sync all: Claude, ChatGPT, Lumo, Gemini (+ AI Studio), desktop apps, Hermes
- [ ] Sync all runs every part even when one fails (error or exception): the failure gets its notice and last-run entry, then the next part runs; only Stop ends the run early
- [ ] Sync all runs only accounts that are logged in or have a pasted session; nothing to run gives a notice (manual only)
- [ ] Provider-wide sync with one account always runs it, so "not logged in" is shown
- [ ] Automatic sync: off at 0, minimum 30 min; a source that stopped with an error is left out of the automatic sync until it syncs without an error again (by hand or otherwise); all other sources keep syncing
- [ ] Sync on startup: once, 10 s after layout ready, quiet like the automatic sync
- [ ] Automatic, start-up, requested and resume runs skip accounts in cooldown (any provider); other accounts still run; a manual sync of a paused account says until when it waits
- [ ] ChatGPT 429: cooldown per account, automatic retry, countdown in status bar, survives restart (cooldown adopted on load)
- [ ] Claude, Gemini, AI Studio and Lumo 429: the same pause [code: rate-limit.ts, cooldown-run.ts]: that one account waits ("<service> answered 429 … Automatic retry scheduled.", a waiting run, not an error, so the source is not paused "until you sync by hand"); the wait is the server's Retry-After where it gives one, at least 30 s, doubling for each 429 in a row up to 10 min; nothing is asked of the service while it lasts ("<service> is cooling down until …"); the retry runs by itself, a run that gets through ends the pause; the state (`cooldownUntil`, `resumeAfter429`) is kept in this computer's file and survives a restart; AI Studio has its own pause, apart from Gemini's — `npm run test:claude` (429, pause rules), `npm run test:sync` (Other-provider 429 retry)
- [ ] Max chats per run (default 3, 0 = no limit), newest first; rest counted as "left for next run"
- [ ] Delay between requests (default 1.5 s, minimum 1 s)
- [ ] Only new or changed chats are fetched
- [ ] Claude: quick list [code: quick-list.ts, sync.ts `listAllChats`]: the chat list as last read is remembered on this computer (`listCatalog`, in the computer file; only uuid, name, dates, project, platform, starred per chat). A sync reads the list page by page (30 chats) and stops at the first page on which every chat is known and unchanged; the rest of the list comes from the remembered rows, so counts, changed chats, missing files, starred and archive checks see every chat as before. Trusted only when the last full read of this account came newest change first from first row to last; a list in another order is read in full every time. The whole list is read: the first time, once a week (chats deleted on claude.ai and star or archive changes on old chats show up then), after a run that failed (not after a rate-limit pause), when "Include archived chats" is switched, and whenever a saved note or raw file is missing (so a deleted note is restored at the next sync, as before) — `npm run test:claude` (quick list, quick list rules)
- [ ] Gemini and AI Studio: quick list, by the same rules as Claude's [code: quick-list.ts `readList`, gemini/api.ts `listChats`, studio/api.ts `listPrompts`]: the list as last read is remembered on this computer (`listCatalog` of the Gemini account and of its AI Studio part, in the computer file); a sync reads page by page (Gemini 50 chats, AI Studio 100 prompts) and stops at the first page on which everything is known and unchanged; the rest comes from the remembered rows, so counts, changed chats, restoring and the safety stop see every chat as before. Trusted only after a full read of that account came newest change first throughout. Gemini's pinned chats are a list of their own, always read to its end: a chat pinned or unpinned on gemini.google.com is marked at the same sync. The whole list is read: the first time, once a week (chats deleted at Google show up then), after a run that failed (not after a rate-limit pause or a Browser link skip), and whenever a saved note or raw file is missing. Lumo has no quick list: it lists chats by creation date and offers no "changed since" (checked 2026-11-27 against Proton's public web client), so its whole list is read every sync — `npm run test:gemini` (Gemini quick list, AI Studio quick list, file gone)
- [ ] One note per chat, every provider (versions.ts): a changed chat rewrites its note in place, same name and place (also after a rename or move); never a second note, never an `(updated …)`, `(recovered)` or `(transcript …)` name
- [ ] Before the raw file is written over, the earlier one is copied to `<name> (version <stamp>)<ext>` beside it (stamp = that version's own update time; ChatGPT's `(older N)` parts with it). Same content again, or a run stopped half way, makes no second copy
- [ ] Note properties: `earlier_versions: N` and `earlier_raw:` links, only when N > 0, written before `unread`
- [ ] Index per chat: `versions` (earlier raw files) and `noteHash` (fingerprint of the note text below the properties)
- [ ] Properties you added are carried over on every rewrite; plugin properties take the new value; `unread` keeps your value when the chat itself did not change (restore, re-render)
- [ ] Edited note (text differs from `noteHash`): setting **When an edited note gets an update**: `copy` (default, saves `<name> (my edits <stamp>).md` first), `keep` (note untouched, raw files still updated), `overwrite`. Named in the sync log
- [ ] Notes from before fingerprints: edited only if the file changed after its sync AND the new transcript no longer holds every old turn
- [ ] Desktop: the raw `.jsonl` is rewritten in place; an earlier copy is kept as a version only when the new file does not start with it; none with Keep raw off. A changed raw folder setting does not move a session's raw copy (the move row does)
- [ ] Hermes: raw `.json` per session (rows from `state.db`) under the raw files folder, linked as `raw:`; a session saved before that keeps its old note text as JSON for its first earlier version
- [ ] ChatGPT: a note rendered differently now (new files, newer plugin) is rewritten in place, counted as "refreshed transcripts". A note that already reads as drawn but has no stored fingerprint (a merge clears it) is not rewritten; its fingerprint is stored again, so it is not read every run
- [ ] Quick check of unchanged chats (Claude file check, ChatGPT file check and redraw; quick-check.ts): after a full check that left nothing to do, a chat's raw files are not read again while their size and modified time, its note and versions, its saved files and the plugin build (version + `main.js` time) stay the same. A deleted file or note (also after the note moved to another folder), a missing file whose next download try is due, a Claude chat view not read yet, a raw file changed on disk, a renamed project, changed earlier versions, a stale note or a new build brings the full check back; a vault that cannot tell file times always does the full check. ChatGPT: a missing file still waiting for its next try (`assetRetries`) does not stop the skip; it is still counted as pending and fetched when due. New keys alone are saved every 50 chats and at the end of the loop (user decision 2026-11-24), not after each chat: a stop in between costs those chats one more read. Results the same as without it. Covered by `npm run test:sync` and `npm run test:claude`
- [ ] Index saved after every chat (into this computer's file, section 11), so a stop loses nothing (quick-check keys alone: in batches, see above)
- [ ] Archive filing is opt-in for ChatGPT and Claude web and requires both archive settings. Confirmed transitions move the indexed bundle without a body download. Retain the active folder and filenames, handle collisions and retry partial moves. Keep other notes and shared assets in place. Progress shows the current account and archive phase, and sync logs show moved/skipped/failed counts.
- [ ] Restore: deleted `.md` rewritten from saved `.json` under its own name and place, with its version info; deleted `.json` fetched again under the same name; both gone = saved like new (Claude) or again under the same names (ChatGPT, Gemini, AI Studio, Lumo)
- [ ] Gemini, AI Studio, Lumo [code: restore.ts]: the deleted note is written from the saved raw file without a request to the provider and outside the per-run limit, counted as restored; a raw file that is damaged, older or of another chat is not used and the chat is fetched again instead — `npm run test:gemini`, `npm run test:lumo` (restore)
- [ ] Missing-guard [code: missing-guard.ts]: many saved chats missing (at least 10 and more than a fifth) stops the sync before anything is read or written, with the hint to use Refresh index. Every source: Claude, ChatGPT, Claude Code cloud, Codex cloud, desktop apps, Gemini, AI Studio, Lumo, Hermes (per profile, checked for all profiles before the first is read) — `npm run test:gemini`, `test:lumo`, `test:hermes` (guard), `test:desktop`
- [ ] Unexpected data shape stops the sync ("could not be verified" class of errors), nothing more is written
- [ ] A request that gets no answer at all (network or TLS error) is tried again after 2 s and 5 s, for Claude, Gemini, AI Studio and Lumo as for ChatGPT [code: net-retry.ts]: only when all 3 tries fail does the sync stop, with "(tried 3 times)" in the message and an entry in the Error logs. Only read requests are repeated — `npm run test:claude` (retry)
- [ ] One chat in an odd shape never stops a sync alone [code: odd-chats.ts]: for Claude, ChatGPT, Gemini, AI Studio and Lumo it is skipped, named in the log ("could not read") and tried again next run; the third odd chat in one run stops the sync ("could not be verified"), as a format change would — `npm run test:claude` (odd chat), `npm run test:sync` (Odd chat and reasoning)
- [ ] Note property `model` [code: naming.ts `modelProperty`]: the models that answered, each once, in the order used; one model is a plain value, several a list; left out when the service does not say. Claude: the chat's `model`. ChatGPT: each answer's `model_slug`, else the chat's `default_model_slug`. Lumo: each answer's `modelID`. (Gemini names the model in the answer's heading, AI Studio in `model`, as before.) Saved ChatGPT notes get it on the next sync (redrawn in place, seen live 2026-11-27: 960 notes); saved Claude and Lumo notes get it when the chat next changes — `npm run test:versions` (model), `test:claude`, `test:lumo`
- [ ] Error messages are redacted (no session key)
- [ ] Sync log line per run appended to the log note (`AI Chats/_ai-chatbridge-log.md` by default; older vaults: renamed once, section 13), with daily-note link, counts, written notes (first 20), stop reason
- [ ] Renames and moves inside Obsidian update the index (debounced save, 1 s)
- [ ] Refresh index finds notes moved outside Obsidian by chat ID; earlier-version files by their unique name
- [ ] Earlier-version files follow renames, folder moves and the raw-file move row (Hermes raw files and Claude Code cloud raw files too)
- [ ] On unload: pending index saved, running sync stopped, login windows closed, no saves afterwards
- [ ] Settings migration from before multiple accounts keeps `data.before-accounts.json` once
